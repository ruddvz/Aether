# GitHub Pages

The Pages site is generated by `scripts/build_site.py`.

Public routes include:

- `/Aether/` generated AETHERIA catalog and collection navigation
- `/Aether/collections.json` machine-readable collection registry and product membership summary
- `/Aether/collections/flight/` active FLIGHT collection containing registered VORTEX
- `/Aether/collections/ocean/` planned OCEAN collection
- `/Aether/collections/botanica/` planned BOTANICA collection
- `/Aether/collections/celestial/` planned CELESTIAL collection
- `/Aether/collections/abstract-motion/` planned ABSTRACT MOTION collection
- `/Aether/products/vx4800/` current approved VORTEX presentation
- `/Aether/products/vx4800/versions/5.2.0/` immutable presentation route
- `/Aether/products/vx4800/fixture.json` published canonical fixture data
- `/Aether/products/vx4800/inspect/` technical coordination inspector
- `/Aether/tools/fixture-editor/` browser-local JSON-Schema fixture proposal editor
- `/Aether/downloads/vx4800/1.3.0/` published coordination GLB assets and optimization manifest

The active product build no longer publishes repository ZIP release packages. Build outputs remain ordinary product/viewer, coordination, interchange-review and Pages artifacts.

The root catalog is registry-driven. Collection membership is derived from each product's canonical fixture `identity.collection` and checked against the collection registry in `project.json`; it is not maintained as a second manual product field. Planned collections remain explicit empty catalog groups until real products are registered.

The fixture proposal editor reads the generated product registry rather than hard-coding VX4800 as its only possible product.

Pages deploys only after canonical validation, Blender source QA, geometry QA, browser-tool tests, Python regression tests and a successful site build. The validation workflow explicitly verifies collection routes, collection membership output, the fixture-editor entry point and required JavaScript modules in the generated Pages tree.

The fixture editor is review-only. Publishing the editor does not grant it repository-write, engineering, manufacturing or release authority. See `docs/FIXTURE_EDITOR.md`.

Collection navigation is catalog-only and likewise does not imply production release or product availability. See `docs/COLLECTION_NAVIGATION.md`.
